1. 기본 원칙
component → unit → in/out 포트 구조를 선언한 뒤 포트 사이를 연결합니다.
전용 문법입니다. PlantUML 문서를 그대로 읽는 기능은 지원하지 않습니다.
명령은 한 줄씩 작성하고 중괄호 }는 별도 줄에 작성하세요.
빈 줄과 //로 시작하는 주석 줄은 무시합니다. 줄 끝 주석은 지원하지 않습니다.
들여쓰기는 자유지만 명령 내 구분 공백은 아래 예제처럼 한 칸씩 작성하세요.
@startuml, @enduml은 지원하지 않습니다.

2. 전체 실행 예제
signal normal "일반 신호" #475569 solid
signal fault "오류 신호" #ef4444 dashed
component input "입력 컴포넌트" #d9e8fb column 1 {
  unit adc "SWU401.1\nDrv_Adc" #d6ead0 {
    in voltage "외부 입력"
    out value "전압값"
  }
}
component control "제어 컴포넌트" #f7ceca column 2 {
  unit led "SWU403.1\nAppl_Led" #ffebcc {
    in value
    out status "결과"
  }
}
adc.value -> led.value normal

3. 컴포넌트와 배치 열
component ID "표시 이름" #RRGGBB column 번호 {
  ...유닛 선언...
}
ID, 이름, 색상, column 번호 모두 필수입니다. 생략 색상은 없습니다.
column은 1~8 정수입니다. 작은 열 번호부터 왼쪽으로 배치합니다.
같은 열의 컴포넌트는 소스 선언 순서대로 위에서 아래로 배치됩니다.
열 번호를 건너뛰어도 빈 열 공간을 만들지는 않습니다.
컴포넌트 ID는 중복 불가하며 컴포넌트 중첩과 빈 컴포넌트를 지원하지 않습니다.

4. 유닛
unit ID "표시 이름" #RRGGBB {
  ...포트 선언...
}
유닛은 반드시 컴포넌트 내부에 선언합니다. ID·이름·색상은 필수입니다.
유닛 ID는 모든 컴포넌트를 통틀어 유일해야 합니다.
같은 컴포넌트의 유닛은 선언 순서대로 세로 배치됩니다.
컴포넌트·유닛·포트 ID에는 영문·숫자·밑줄을 사용할 수 있습니다.
혼동을 줄이려면 영문 또는 밑줄로 시작하세요. 한글 ID·공백·하이픈은 지원하지 않습니다.
표시 이름에는 한글·공백을 사용할 수 있으며 큰따옴표가 필요합니다.
이름의 \n은 그림에서 줄바꿈됩니다. 이름 안 큰따옴표 이스케이프는 지원하지 않습니다.
유닛의 포트가 없어도 됩니다. 다이나믹의 io 문법은 사용할 수 없습니다.

5. 입력·출력 포트
in voltage "입력 전압"
out mode "동작 모드"
in fault
in은 유닛 왼쪽, out은 오른쪽입니다. 포트 ID는 필수, 표시 이름은 선택입니다.
이름을 생략하면 빈 라벨로 표시합니다. ID가 자동으로 그림에 표시되지는 않습니다.
동일 유닛에서는 in/out을 포함해 같은 포트 ID를 두 번 사용할 수 없습니다.
다른 유닛에서는 같은 포트 ID를 사용해도 됩니다(예: adc.value, led.value).
포트 선언 순서는 유지합니다. 입력 포트는 가능하면 송신 포트와 높이를 맞춰 직선으로 연결합니다. 최소 포트 간격은 18px이며, 유닛 높이는 기본 크기보다 최대 48px까지만 추가 확장합니다. 높이를 맞출 수 없으면 직각 경로를 사용합니다.
외부 선 스타일 지정: in tail "Vcc_Tail" signal hw
출력도 동일합니다: out tx "TxData" signal hw
signal 뒤에는 정의된 신호 종류 ID를 적습니다. 색과 선 종류는 해당 signal 선언을 따릅니다.
생략 시 normal(기본 #475569, solid)을 사용합니다. 표시 이름을 생략한 in tail signal hw도 가능합니다.
이 지정은 연결 상대가 없는 외부 선에 적용됩니다. 내부 연결선은 연결문 끝의 신호 종류를 따릅니다.
연결하지 않은 포트는 외부 입출력으로 표시합니다. 입력은 왼쪽, 출력은 오른쪽으로 24px 선이 나옵니다.
별도 연결 명령은 필요 없습니다. 선의 색상·종류는 normal 신호 설정을 따르며 끝에는 점을 표시하지 않습니다.

6. 신호 연결과 분기
adc.value -> led.value
adc.value -> led.value fault
adc.value -> monitor.voltage normal
연결은 컴포넌트 중괄호 밖에 작성합니다.
형식: 송신유닛.출력포트 -> 수신유닛.입력포트 [신호종류ID]
[ ]는 선택 항목 설명이며 소스에는 넣지 않습니다.
생략 종류는 normal입니다. out → in만 허용합니다.
수신 컴포넌트의 column이 송신 컴포넌트보다 커야 합니다.
같은 열 연결, 역방향 연결, 자기 연결, <- / --> / <-- 기호는 지원하지 않습니다.
파선은 -->가 아니라 signal의 dashed로 설정합니다.
중간 열을 건너뛰는 자동 연결이 다른 컴포넌트 박스를 통과하면 박스 아래의 여유 공간으로 우회합니다.
배선 공간은 실제 세로 구간을 기준으로 계산합니다. 세로 구간이 겹치지 않는 신호는 같은 레인을 재사용하고, 겹치는 신호만 24px 간격으로 분리합니다. 이동값이 반영된 구간으로 다시 계산하며 레인 내부 좌우 조정은 ±4px로 제한합니다. 가로·세로선의 교차는 남을 수 있습니다.
같은 출력·같은 종류의 연결은 세로 분기선을 공유합니다. 세 방향 이상으로 갈라지는 실제 분기점에만 점을 표시하며, 단순 굴곡과 포트 끝에는 점을 표시하지 않습니다.
단순 교차는 연결을 의미하지 않습니다. 복잡한 연결의 교차·중첩 회피는 보장하지 않습니다.

7. 신호 종류 사용자 설정
signal ID "범례 이름" #RRGGBB 선종류
signal normal "일반 신호" #475569 solid
signal fault "고장 신호" #ef4444 dashed
signal hw "HW 인터페이스" #16a34a dotted
signal diagnostic "진단 통신" #8050cc dashdot
adc.value -> led.value diagnostic

signal은 컴포넌트 밖에 선언합니다. 같은 ID는 한 번만 정의할 수 있습니다.
기본 종류 normal/fault/hw를 재정의하거나 새 ID를 추가할 수 있습니다.
신호 ID는 영문·밑줄로 시작하고 이후 영문·숫자·밑줄을 사용합니다.
범례 이름에는 큰따옴표·역슬래시·\n을 사용할 수 없습니다.
solid: 실선
dashed: 파선(선 8px, 공백 5px)
dotted: 점선(선 2px, 공백 5px)
dashdot: 일점쇄선(선 8px, 공백 4px, 선 2px, 공백 4px)
선 이름은 정확히 소문자로 입력합니다.
선 종류·색상·이름은 범례와 SVG/PNG에 함께 반영됩니다.
종류를 추가하면 상단 오른쪽 범례가 넓어집니다. 사용하지 않은 종류도 범례에 나타납니다.
설정은 소스에 포함되므로 탭 복제·소스 저장·프로젝트 저장에도 유지됩니다.

8. 색상 기본값과 예제의 차이
signal을 전혀 선언하지 않은 경우:
normal → 일반 신호 / #475569 / solid
fault → 고장 신호 / #ef4444 / solid
hw → HW–SW 인터페이스 / #16a34a / solid

기본 예제는 fault를 dashed, hw를 dotted로 명시적으로 바꿉니다.
즉 예제의 파선·점선은 엔진의 생략 기본값이 아니라 예제 설정입니다.
컴포넌트·유닛 색상은 필수이며 생략 기본값이 없습니다.
예제 색상: BSP 컴포넌트 #d9e8fb, App 컴포넌트 #f7ceca,
BSP 유닛 #d6ead0, App 유닛 #ffebcc.
색상은 #RRGGBB만 지원합니다. #RGB, 색상 이름, 알파 채널은 지원하지 않습니다.
일반 연결선 두께 1.5px, 범례 선 2px, 분기점 반지름 3px.
분기점은 해당 신호 색상으로 채웁니다. 범례: 흰색 배경 / #94a3b8 테두리.
그림 배경: 흰색. 텍스트: 기본 검정, Arial/sans-serif, 일반 12px·포트 라벨 11px.
포트 라벨의 흰색 외곽은 지나가는 선과 글자를 구분하기 위한 표시입니다.

9. 배치와 화면 간격
유닛 최소 폭 160px·최소 높이 100px. 이름 길이와 포트 개수에 맞춰 커집니다.
열 간격은 열 사이 여유 공간을 조절합니다. 라벨 길이와 배선 공간은 별도로 확보합니다.
행 간격은 포트 수에 따른 박스 높이와 유닛·컴포넌트 세로 여백에 반영됩니다.
세로 배선 레인 간격은 24px입니다. 열 간격 값 자체가 선 간격을 뜻하지는 않습니다.
긴 신호 이름 뒤에 선이 꺾일 공간을 확보하므로 열별 실제 너비는 달라집니다.

10. 오류 해결
컴포넌트 이동
컴포넌트 박스를 클릭하여 선택합니다. 위·아래 방향키는 2px, Shift와 함께 누르면 10px 이동합니다. 좌우 방향키는 허용된 범위에서 한 열씩 이동합니다. 연결선은 즉시 다시 계산합니다.
내부 유닛과 포트는 함께 이동합니다. 유닛 박스 클릭 후 방향키로 개별 이동할 수 있습니다.
입력 컴포넌트보다 오른쪽, 출력 컴포넌트보다 왼쪽 열만 허용됩니다. 가능한 열이 하나라면 세로로만 이동합니다.
같은 열의 박스가 겹치면 아래로 밀어 간격을 확보합니다. 따라서 지정 위치와 최종 위치는 달라질 수 있습니다.
이동은 소스에 다음 형식으로 저장됩니다. 컴포넌트 밖에서 한 번만 선언하세요.
place monitor column 2 y 400
column은 1~8, y는 0~10000px이며 상단 범례 공간을 위해 실제 y는 110px 이상입니다.
전체 자동 배치 복원은 place와 route를 모두 제거합니다. 원래 component의 column 선언으로 돌아갑니다.

유닛 위치는 부모 컴포넌트 기준으로 unitplace func x 30 y 60 형태로 저장합니다. x는 최소 12px, y는 제목 영역 아래인 최소 42px이며 최대 10000px입니다. 컴포넌트는 유닛을 포함하도록 확장됩니다. 키보드 이동 시 다른 유닛과 최소 8px 간격을 유지하며 겹치는 이동은 제한됩니다. 전체 자동 배치 복원은 unitplace도 제거합니다.

선 수동 조정
연결선을 클릭하면 선택 표시가 나타납니다. 해당 소스가 강조되고 방향키는 2px씩 이동합니다.
Shift+방향키는 10px입니다. 소스 입력 중 방향키는 텍스트 편집에 사용됩니다.
같은 출력·신호 종류의 분기 경로를 함께 이동하며 포트 끝점은 고정됩니다.
상하 이동 시 끝점 근처에 직각 꺾임이 추가됩니다. 이름과 박스 위치는 유지됩니다.
전체 자동 배치 복원은 모든 route와 place 명령을 제거합니다.
이동값은 소스에 아래 형태로 저장됩니다(각 축 -500~500px).
route adc.value normal 20 -10
양수 X는 오른쪽, 양수 Y는 아래쪽입니다. signal 정의와 연결은 그대로 유지됩니다.
수동 이동 시에도 중간 열의 박스 우회를 유지합니다. 세로 배선은 열 사이로, 아래쪽 우회선은 박스 아래로 이동 범위가 제한됩니다. 선끼리의 교차는 허용됩니다. 미연결 포트 선은 조정 대상이 아닙니다.

• 정의되지 않은 신호 종류: 연결 끝의 ID와 signal 선언을 비교하세요.
• out에서 in으로 연결: 양 끝 ID 존재 여부와 포트 방향을 확인하세요.
• 오른쪽 열로 연결: 수신측 column 번호를 더 크게 지정하세요.
• 포트 ID 중복: 같은 유닛의 입력과 출력도 서로 다른 ID를 사용하세요.
• 닫는 괄호 필요: unit과 component를 각각 }로 닫으세요.
• 문법 오류: 필수 색상·column·큰따옴표·한 칸 공백을 확인하세요.

공통 편집·저장 안내
────────────────────────────────────
• 프로젝트 이름은 상단 입력창, 다이어그램 이름은 하단 이름 변경에서 수정합니다.
• 탭 추가는 빈 소스를 만들고, 탭 복제는 소스·이름·간격·배율을 복사합니다.
• 탭을 드래그하여 순서를 바꿉니다. 마지막 탭 하나는 삭제할 수 없습니다.
• 프로젝트 저장/열기: 모든 탭과 설정을 JSON 파일로 저장·복원합니다.
• 소스 저장/불러오기: 현재 탭만 대상으로 합니다. 불러오기는 현재 소스를 교체합니다.
• 소스 파일의 // @diagram-name: "이름" 주석은 저장 시 추가됩니다.
• SVG/PNG 내보내기는 현재 탭의 정상 그림만 저장합니다. 오류 중에는 비활성화됩니다.
• PNG는 기본 2배 해상도로 생성하며 가장 긴 변이 8192px을 넘으면 배율을 줄입니다.
• 저장 창 지원 브라우저는 이름·폴더를 선택합니다. 미지원 브라우저는 이름 입력 후 다운로드합니다.
• 자동 저장은 현재 브라우저·접속 주소에 종속됩니다. 파일 백업은 프로젝트 저장을 사용하세요.
• 다이나믹과 아키텍처는 별도로 저장하며 다른 종류의 프로젝트를 열 수 없습니다.
• 소스 새 창은 현재 탭을 따라갑니다. 양쪽 입력은 즉시 반영되고 오류도 새 창에 표시됩니다.
• 문법 가이드는 별도 창으로 열립니다. 팝업 차단 시 해당 사이트의 팝업을 허용하세요.
• 원래 편집기를 닫거나 새로고침하면 팝업도 닫힙니다.
• 줄 번호는 실제 소스 행 기준입니다. 화면 자동 줄바꿈은 실제 행을 추가하지 않습니다.
