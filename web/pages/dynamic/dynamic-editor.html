1. 기본 원칙
전용 텍스트 문법이며 전체 PlantUML 문법을 지원하지 않습니다.
한 명령은 한 줄에 작성합니다. 빈 줄과 //로 시작하는 줄은 무시합니다.
줄 끝 주석은 지원하지 않습니다. 주석은 별도 줄에 작성하세요.
@startuml, @enduml은 있어도 무시하므로 생략 가능합니다.
명령어는 소문자이며 ID의 대소문자를 구별합니다.

2. 가장 간단한 예제 (전체 복사 가능)
unit input "입력 유닛"
unit output "출력 유닛"
input -> output : 요청
output --> input : 응답

3. 컴포넌트와 유닛
component "컴포넌트 이름" #d9e8fb {
  unit adc "Drv_Adc\n(SWU101.1)" #d6ead0 io #ffcc80
}
unit led "Appl_Led" #ffebcc
adc -> led : VINVOL_TAIL

component "이름" [색상] {
  unit ID "표시 이름" [유닛 색상] [io 작은박스색상]
}
※ 위의 [ ]는 선택 항목 표시이며 소스에 입력하지 않습니다.
컴포넌트는 생략할 수 있습니다. 독립 유닛과 소속 유닛을 함께 사용할 수 있습니다.
컴포넌트 안에 다른 컴포넌트를 넣을 수 없고, 빈 컴포넌트는 오류입니다.
유닛은 최소 1개 필요합니다. 유닛 선언 자체에는 중괄호를 붙이지 않습니다.
유닛 ID는 영문·밑줄로 시작하고 이후 영문·숫자·밑줄을 사용합니다.
ID는 소스 전체에서 유일해야 합니다. 표시 이름과 연결용 ID는 다릅니다.
표시 이름은 큰따옴표로 감싸고, 줄바꿈은 \n, 따옴표 표시는 \"로 작성합니다.
컴포넌트·유닛은 선언 순서대로 왼쪽에서 오른쪽으로 배치합니다.

4. 메시지와 방향
input -> output : 실선으로 input에서 output으로
input <- output : 실선으로 output에서 input으로
input --> output : 점선으로 input에서 output으로
input <-- output : 점선으로 output에서 input으로
input -> input : 자기 자신 호출
input -> output #009900 : 첫 번째 항목\n두 번째 항목

메시지의 : 뒤 이름은 필수입니다. 색상은 화살표 뒤 대상 ID와 : 사이에 넣습니다.
화살표 기호는 송수신 방향을 뜻하며 실제 좌우 위치는 유닛의 선언 순서에 따릅니다.
메시지는 작성 순서대로 위에서 아래로 배치합니다.
메시지에 쓰인 모든 ID는 반드시 unit으로 선언해야 합니다.

5. 색상과 생략 시 기본값
색상 형식: #RGB 또는 #RRGGBB. 대소문자 구별 없이 사용합니다.
색상 이름(red), 투명도 포함 #RRGGBBAA는 지원하지 않습니다.
컴포넌트 배경: #f8cfc8
유닛 배경: #ffebcc
작은 입출력 박스: #ffebcc (유닛 색상과 독립적)
메시지 선·화살표: #3030ff
생명선: #202020 / 두께 2px / 점선 7px, 공백 6px
문자: #111827 / Arial, sans-serif
컴포넌트·유닛·작은 입출력 박스는 테두리 없이 표시합니다.
예제에 명시된 색상은 위 생략 기본값보다 우선합니다.
io를 생략하면 유닛의 색상을 따라가는 것이 아니라 #ffebcc를 사용합니다.

6. 간격과 배치
space 30
이 위치 이후 메시지에 30px의 세로 여백을 추가합니다. 0~1000 정수만 허용합니다.
빈 줄을 추가하는 것만으로 그림 간격은 바뀌지 않습니다.
열 간격은 메시지에 필요한 여백 계산에 반영되므로 모든 박스 사이 실측 거리가 같지는 않습니다.
긴 제목·유닛 이름·메시지는 잘리지 않도록 필요한 공간을 확보합니다.
유닛 기본 폭은 160px이며 긴 이름이면 넓어집니다. 명시적 \n만 그림에서 줄바꿈됩니다.
행 간격은 메시지 사이 기본 간격입니다. 여러 줄 메시지와 자기 호출은 더 넓어질 수 있습니다.
제목/유닛 텍스트는 약 13.33px, 메시지는 약 12.33px, 줄 간격은 20px입니다.

7. 자주 발생하는 오류
• 선언하지 않은 유닛: 화살표의 ID와 unit의 ID를 비교하세요.
• 중복된 유닛 ID: 표시 이름이 아닌 연결용 ID를 각각 다르게 지정하세요.
• 닫는 중괄호 필요: component마다 별도 줄의 }를 넣으세요.
• 문법 오류: 따옴표, : 위치, 색상 형식, 지원 화살표를 확인하세요.
• 아키텍처용 in/out, column, signal 명령은 이 편집기에서 지원하지 않습니다.

공통 편집·저장 안내
────────────────────────────────────
• 프로젝트 이름은 상단 입력창, 다이어그램 이름은 하단 이름 변경에서 수정합니다.
• 탭 추가는 빈 소스를 만들고, 탭 복제는 소스·이름·간격·배율을 복사합니다.
• 탭을 드래그하여 순서를 바꿉니다. 마지막 탭 하나는 삭제할 수 없습니다.
• 프로젝트 저장/열기: 모든 탭과 설정을 JSON 파일로 저장·복원합니다.
• 소스 저장/불러오기: 현재 탭만 대상으로 합니다. 불러오기는 현재 소스를 교체합니다.
• 소스 파일의 // @diagram-name: "이름" 주석은 저장 시 추가됩니다.
• SVG/PNG 내보내기는 현재 탭의 정상 그림만 저장합니다. 오류 중에는 비활성화됩니다.
• PNG는 기본 2배 해상도로 생성하며 가장 긴 변이 8192px을 넘으면 배율을 줄입니다.
• 저장 창 지원 브라우저는 이름·폴더를 선택합니다. 미지원 브라우저는 이름 입력 후 다운로드합니다.
• 자동 저장은 현재 브라우저·접속 주소에 종속됩니다. 파일 백업은 프로젝트 저장을 사용하세요.
• 다이나믹과 아키텍처는 별도로 저장하며 다른 종류의 프로젝트를 열 수 없습니다.
• 소스 새 창은 현재 탭을 따라갑니다. 양쪽 입력은 즉시 반영되고 오류도 새 창에 표시됩니다.
• 문법 가이드는 별도 창으로 열립니다. 팝업 차단 시 해당 사이트의 팝업을 허용하세요.
• 원래 편집기를 닫거나 새로고침하면 팝업도 닫힙니다.
• 줄 번호는 실제 소스 행 기준입니다. 화면 자동 줄바꿈은 실제 행을 추가하지 않습니다.
• Tab 키는 공백 2칸을 입력합니다. 문법 오류가 나면 행 번호와 오류 문구를 확인하세요.
• 오류가 생기면 같은 탭의 마지막 정상 그림을 유지하며 작성 중 소스는 프로젝트에 보관합니다.

화면 설정 기본값
────────────────────────────────────
열 간격: 42, 입력 범위 24~240
행 간격: 48, 입력 범위 30~160
확대: 100%, 입력 범위 50~200%
화면에 맞춤: 가로·세로 가용 공간으로 배율 계산(50~200% 제한)
큰 그림은 50%에서도 스크롤이 남을 수 있습니다. 확대는 내보낸 원본 크기를 바꾸지 않습니다.
소스 영역 기본 너비: 312px. 경계선을 드래그하거나 방향키로 조절하고 Home으로 초기화합니다.
소스 글꼴: Consolas, 없으면 monospace / 12px / 줄 높이 22px
기본 프로젝트 이름: 새 프로젝트 / 최초 다이어그램 이름: 새 다이어그램
