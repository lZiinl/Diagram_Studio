# Diagram Studio

SW 설계 문서용 텍스트 기반 다이어그램 편집기입니다. 외부 라이브러리와 서버 연결 없이 브라우저에서 동작합니다.

## 실행 및 검증

- 설치 없이 실행: 루트 open-diagram-studio.html 또는 web/diagram-hub.html을 브라우저에서 열기
- 개발 서버: Node 22 이상에서 `npm start` → http://127.0.0.1:8765
- 테스트: `npm test`
- 배포 산출물: `npm run build` → dist/

브라우저 실행에는 외부 패키지가 필요하지 않습니다. 개발할 때는 Node 22.13 이상과 pnpm 11.25.0을 사용하고 `pnpm install --frozen-lockfile`로 포맷터를 설치합니다. pnpm 버전은 package.json에 고정되어 있습니다.

`pnpm format`으로 코드를 정리하고 `pnpm format:check`로 확인합니다. `pnpm test`와 `pnpm build`로 검증·빌드를 실행합니다. CI도 같은 순서로 확인합니다. 실행·테스트·빌드만 필요한 경우에는 `node scripts/serve.cjs`, `node tests/dynamic.test.cjs`, `node tests/site.test.cjs`, `node tests/build.test.cjs`를 직접 실행할 수 있습니다.

## 코드 작성 규칙

- 공백 2칸 들여쓰기와 100자 기준 줄 길이를 사용합니다.
- 한 줄에는 한 문장, 변수는 선언별로 작성하고 처리 단계 사이에 빈 줄을 둡니다.
- 함수·변수는 목적을 드러내는 이름을 사용합니다.
- 복잡한 배치 계산과 예외 처리 이유는 한국어 주석으로 설명합니다.
- 파싱·배치·렌더링·화면 이벤트를 분리합니다.

자세한 규칙은 [AGENTS.md](AGENTS.md)에 있습니다. `.editorconfig`와 Prettier 설정, CI 형식 검사가 이를 뒷받침합니다.

기존 작업은 이전 편집기에서 소스로 저장한 뒤 새 페이지에서 불러오세요. 파일 경로나 접속 주소가 바뀌면 브라우저 자동 저장이 이어지지 않을 수 있습니다.

## 다이나믹 다이어그램 문법

유닛 박스는 `Appl_WakeUpSleep`이 들어가는 160px을 기본 폭으로 사용하고, 더 긴 이름에는 필요한 폭을 확보합니다. 컴포넌트 제목과 메시지는 강제로 줄바꿈하지 않습니다. 제목에 맞춰 컴포넌트를 넓히고 내부 유닛을 가운데 정렬하며, 긴 메시지는 열 사이 공간을 늘려 표시합니다. 따라서 내용에 따라 실제 여백은 달라질 수 있습니다. 줄바꿈이 필요하면 소스에 `\n`을 직접 넣으세요.

상세설계서는 컴포넌트 없이 유닛만 선언할 수도 있습니다. 이때 컴포넌트 박스는 그리지 않습니다. 컴포넌트 안의 유닛과 독립 유닛을 함께 선언해도 소스 순서대로 배치됩니다.

```text
unit input "Input" #d6ead0
unit function "Function" #CC99FF io #CC99FF
input -> function : 요청
input <-- function : 응답
```

컴포넌트·유닛·입출력 박스는 테두리 없이 표시됩니다. 유닛 색상과 작은 입출력 박스 색상은 별도로 지정합니다.

```text
unit input "Input" #d6ead0 io #ffcc80
```

첫 색상은 유닛 박스, `io` 뒤 색상은 작은 박스입니다. `io`를 생략하면 작은 박스는 기본색 `#ffebcc`를 사용합니다. 그림의 텍스트는 기존보다 1pt 크게 표시됩니다.

소스 왼쪽에 실제 행 번호와 오류 행 강조가 표시됩니다. 긴 줄은 소스 영역 너비에 맞춰 자동으로 줄바꿈됩니다. 화면에서 여러 줄로 보이더라도 실제 소스에는 줄바꿈을 추가하지 않으며 원래 행 번호를 유지합니다. 소스와 미리보기 사이 경계를 드래그하거나 경계에 포커스를 놓고 좌우 방향키로 너비를 조절하세요. 기본 너비는 312px이며 Home 키로 초기화할 수 있습니다. 너비는 브라우저에 저장됩니다. 기본 예제에서는 메시지 사이 `space` 명령을 제거했으며 직접 작성한 소스의 `space` 문법은 계속 지원합니다.

### 프로젝트와 여러 탭

- 하단의 **+ 탭 추가**로 빈 다이어그램을 추가하고 탭 이름을 눌러 전환합니다.
- **탭 복제**는 현재 탭 바로 뒤에 소스·행/열 간격·확대율을 복사한 독립 탭을 만듭니다. 이름은 `(복사본)`, `(복사본 2)`처럼 구분됩니다.
- **이름 변경** 또는 탭 더블클릭으로 탭 이름을 바꿉니다. 프로젝트 이름은 상단 왼쪽 로고 옆에서 수정합니다.
- **탭 삭제**는 확인 후 삭제하며, 마지막 탭 하나는 유지합니다.
- 각 탭은 소스·이름·열 간격·행 간격·확대율을 따로 보관합니다. 문법 오류가 있는 작성 중 소스도 유지합니다.
- **프로젝트 저장/열기**는 모든 탭과 프로젝트 이름을 JSON 파일 하나로 저장·복원합니다.
- 기존 **소스 저장·SVG·PNG**는 선택한 탭만 내보냅니다. 소스 불러오기도 선택한 탭에 적용됩니다.

프로젝트는 현재 브라우저에 자동 저장됩니다. 이전 버전의 단일 작업은 첫 탭으로 이관합니다. 앱 내부 탭 기능이며 다른 브라우저 창 사이의 공동 편집·동기화는 지원하지 않습니다.

### 메시지 방향

```text
input -> output : input에서 output으로 실선 전송
input <- output : output에서 input으로 실선 전송
input --> output : input에서 output으로 점선 전송
input <-- output : output에서 input으로 점선 전송
```

화살표가 가리키는 유닛이 수신자입니다. 색상은 기존처럼 화살표 식 뒤에 지정할 수 있습니다.

현재 **탭 이름**은 브라우저에 자동 저장되며 소스·SVG·PNG의 기본 파일 이름으로 사용됩니다. 소스 파일에는 이름 주석이 포함되어 다시 불러올 때 복원됩니다. 이름 주석이 없는 소스는 파일 이름을 사용합니다.

저장 버튼을 누르면 지원 브라우저(Chrome·Edge 등)의 HTTPS 환경에서 파일 이름과 저장 폴더를 선택하는 창이 열립니다. 저장 창 API를 지원하지 않는 브라우저는 이름 입력 후 일반 다운로드로 저장하며, 폴더 선택은 브라우저의 “저장 위치를 매번 확인” 설정을 사용합니다. 다이어그램 이름은 문서와 파일 식별용이며 그림 내부에는 표시하지 않습니다.

기본 예제는 컴포넌트 사이에 빈 줄 두 개를 둡니다. 자동 저장된 과거 기본 예제도 같은 간격으로 갱신하지만 수정한 사용자 소스는 유지합니다.

PlantUML과 유사한 전용 문법이며 전체 PlantUML과 호환되지 않습니다.

```text
component "입력" #dbeafe {
  unit input "Input\n(SWU101.1)" #d6ead0
}
component "출력" #f7ceca {
  unit output "Output" #ffebcc
}
input -> output #009900 : Signal
output --> input : Response
output -> output : Internal call
space 30
```

유닛 ID는 영문·밑줄로 시작하고 영문·숫자·밑줄을 사용합니다. 선언 순서가 열 순서입니다. 색상은 #RGB 또는 #RRGGBB, 줄바꿈은 \n, 여백은 space를 사용합니다.
